## 3. What this segment actually did

### 3.1 Deleted dead code

`crates/protocol-droid-schema/src/generator/naming.rs` (305 lines) — **deleted, staged**.

It was a *parallel* naming implementation: its own `RUST_KEYWORDS` list, its own
`words()` / `push_camel_words()` / `field_ident()`, and its own `#[cfg(test)] mod tests`.
It had **zero callers** — `generator/mod.rs` declares only `pub mod emit;` and
`pub mod schema_model;`. It survived in the tree because `build.rs` `#[path]`-includes
`emit.rs` and `schema_model.rs`, so the file compiled without ever being wired to
anything.

Its naming rules had *drifted* from the live ones in `emit.rs` (it used the
trailing-underscore convention universally; the live code uses `r#` for keywords).
Two live bugs were hiding behind the dead file:

### 3.2 Bug #1 — `r#self` / `r#super` / `r#crate` are compile errors

**The dead branch.** The original `field_ident` was:

```rust
if RESERVED.iter().any(|r| *r == snake) {
    format!("r#{snake}")          // <-- fires for "self"/"super"/"crate"
} else if is_keyword(&snake) {
    format!("{snake}_")           // <-- UNREACHABLE
}
```

`is_keyword(name)` is `RESERVED.contains(&name)` — the *same predicate* as the first
branch. The `else if` could never run, so the trailing-underscore fallback existed in
source but never executed. Every keyword therefore became `r#word`, and four of those
are not legal Rust:

> rustc rejects raw-identifier syntax for exactly four words: `self`, `Self`, `super`,
> `crate`. `r#self` is not an identifier. Neither is bare `self` as a field name.

**The fix** (`emit.rs`, `field_ident`): check a new `NOT_RAW_IDENTIFIABLE` list
*first* → `{snake}_`; then `RESERVED` → `r#{snake}`; then the pre-existing
leading-underscore trim; else bare `snake`.

```rust
const NOT_RAW_IDENTIFIABLE: &[&str] = &["self", "super", "crate"];
```

The list is matched against the *lowercased snake* form, so a member named `Self`
arrives as `self` and is covered by that one entry — no separate `"Self"` needed.

### 3.2b Bug #3 (found late, during primer verification) — digit-leading member names

**Not yet fixed.** Found while verifying the primer's claims; recording it here because
it is the same bug class and it is *not* covered by the two fixes above.

`field_ident` output is used directly as the Rust field name (`emit.rs:1184-1199`
writes `pub {field}: {ty}`), and `to_snake` does **not** guard a leading digit:

```
to_snake("2fa")    -> "2fa"
field_ident("2fa") -> "2fa"      // ILLEGAL — `pub 2fa: u8` does not compile
```

Verified with rustc, edition 2024:

```
error: expected identifier, found `2fa`
help: identifiers cannot start with a number
```

`pub _2fa: u8` compiles fine. Note the asymmetry: `type_ident` *does* guard this
(`if i == 0 && ch.is_ascii_digit() { out.push('_') }`, `emit.rs:1467-1470`) — only the
*field* path is unguarded.

**Why the dead file mattered here.** `naming.rs`'s `field_ident` produced `_2fa`
(trailing-underscore convention with a leading-underscore guard). The live
implementation regressed to bare `2fa`. So deleting the dead file did not cause this,
but the dead file was the only place the case was handled — and it had a test for it
(`field_ident("2fa") == "_2fa"`).

**Current blast radius: zero.** Scanned all six vendored revisions for property names
beginning with a digit: **NONE**. So this cannot bite today. It would bite the first
time upstream ships a member like `"2fa"` — and the failure is a *build* failure in
the generated crate, not a runtime one, so it would be caught immediately rather than
silently. Still worth fixing, because the whole point of this segment was to make the
identifier rules provably correct rather than accidentally correct.

**Suggested fix** (mirrors `type_ident`, and keeps `#[serde(rename)]` doing the wire
work — the emitter already writes `#[serde(rename = "{prop_name}")]` whenever
`field != *prop_name`):

```rust
} else if snake.starts_with(|c: char| c.is_ascii_digit()) {
    // A member name may start with a digit — upstream's `"2fa"` does. Rust
    // identifiers may not, so the field gains a leading underscore and keeps
    // the serde rename back to the wire name.
    format!("_{snake}")
}
```

Order matters: this check must come **before** the leading-underscore-trim branch
(which would otherwise strip the very underscore that makes it legal), and after the
`RESERVED` / `NOT_RAW_IDENTIFIABLE` branches.

### 3.3 Bug #2 — `gen` was missing from `RESERVED`

Rust 2024 (this crate's edition) reserves `gen`. It is *not* a strict keyword, but it
cannot be used as an identifier at all: `type gen = u8;` and `struct gen;` both fail to
compile in edition 2024, while `type gen_ = u8;` compiles. The old `RESERVED` list had
no `gen`, so a schema member named `gen` would have emitted a bare `gen` field.

**The fix:** added `"gen"` to `RESERVED`. It now maps to `r#gen` (which *is* legal —
verified).

Note: `union` was already in `RESERVED` and is not actually reserved in 2024. It was
left in place deliberately — a plausible MCP member name, and reserving it costs
nothing. The doc comment on `RESERVED` now says so explicitly.

## 6. The remaining work, in detail

### 6.1 Regression tests — placement decision

Two options:

- **`tests/generation.rs`** (integration). Lower risk. `emit::field_ident` is `pub`, and
  the file already imports `protocol_droid_schema::generator::emit`. But: the file
  loads real vendored schemas; testing `field_ident("self")` needs no schema at all.
- **`#[cfg(test)] mod tests` inside `emit.rs`**. Precedented by `manifest.rs`. Tests
  the function where it lives, which is where a future edit will look. Caveat: the
  library's `generator` module is behind `#[cfg(feature = "codegen")]`, so these tests
  only run with `--all-features` — which `cargo l` and CI both use, and `cargo test
  --workspace --all-features` (the project preflight) uses.

**Recommendation: a `#[cfg(test)] mod tests` in `emit.rs`.** `field_ident` is a pure
function with no schema dependency, and the tests belong next to the rules they pin.
Gate it with `#[cfg(all(test, feature = "codegen"))]` if the library-side compile
needs it — verify by running both `cargo test -p protocol-droid-schema` (default
features, codegen on) and `cargo test -p protocol-droid-schema --no-default-features`.

Note the `#[path]`-include interaction: `emit.rs` is compiled into `build.rs` too, but
`build.rs` is never compiled in test mode, so `#[cfg(test)]` content is excluded there.
`manifest.rs` establishes the precedent — follow it exactly.

### 6.2 Regression tests — what to assert

Minimum set:

```rust
// The four raw-rejected words take a trailing underscore, never r#.
assert_eq!(field_ident("self"),  "self_");
assert_eq!(field_ident("super"), "super_");
assert_eq!(field_ident("crate"), "crate_");
assert_eq!(field_ident("Self"),  "self_");   // snake-cased to "self"

// The 2024 reserved word.
assert_eq!(field_ident("gen"), "r#gen");     // never bare "gen"

// The pre-existing raw-identifier path still works — PIN IT.
assert_eq!(field_ident("type"), "r#type");

// Digit-leading member names (see §3.2b). If bug #3 is fixed, expect "_2fa";
// if not fixed, this test documents the bug — decide which.
assert_eq!(field_ident("2fa"), "...");   // <-- fill in
```

Plus two property-style tests over the real vendored data:

- **Collision test:** for every definition of every revision, collect
  `field_ident(name)` over its properties; assert no two members of one definition
  collapse to the same Rust identifier. (Already verified manually: zero collisions
  under the new rules — the test pins it.)
- **Legality test:** assert every emitted identifier is a legal Rust identifier
  (bare or raw), and that no `RESERVED` word maps to a bare identifier and no
  `NOT_RAW_IDENTIFIABLE` word maps to a raw identifier.

`assert_matches!` / `debug_assert_matches!` are available (dev-dep `assert_matches` is
present, and both are stabilized) and print `Debug` on failure — prefer them over
`assert!(matches!(..))`.

### 6.3 Hard constraints on the test code

From `AGENTS.md` (non-negotiable, and `cargo l` enforces them across `--all-targets`):

- **No `.unwrap()`, `.expect()`, `.expect_err()`, `panic!()`.** Return
  `Result<(), E>` from the test and use `?`. When fallible calls answer unrelated
  error types, collect them in a small `enum Failure` with a `From` impl each (see
  `engine.rs` and `registry.rs` for the pattern).
- **No index slicing** — `&vec[i]`, `&s[0..n]`, `arr[0]`, `s[..n]`. Use `.get(i)` with
  explicit handling, or `slice.first()`, or `let [first, ..] = slice else { .. }`.
  `clippy::indexing_slicing` does **not** fire on a constant index into a fixed-size
  array (`cases[0]` on `[(..); N]` passes clean) — that is exactly the case a test
  reaches for, so the lint will not catch it for you. **Iterate instead.**
- **Do NOT add `#[expect(clippy::unwrap_used, ...)]` to a new test module.** The
  attribute only grandfathered code that predates the rule; adding one to a new test
  is how the rule gets skipped wholesale rather than obeyed.
- `#[allow(clippy::...)]` is forbidden outright. `#[expect(..., reason = "...")]` is
  allowed with a reason.
- Prefer `.is_multiple_of(n)` over `% n == 0`.
- Doc comments on public items need `# Examples` / `# Errors` / `# Panics` sections
  where the function can fail in those ways.

## 9. Facts worth not re-deriving

- **Raw identifiers work for every reserved word except `self`, `Self`, `super`,
  `crate`.** Verified with rustc, edition 2024. Everything else → `r#word`.
- **`gen` is reserved in Rust 2024** but is not a strict keyword. Cannot be an
  identifier in any form; `gen_` and `r#gen` are both legal.
- **`is_keyword(name)` is `RESERVED.contains(&name)`** — the identical predicate to
  `RESERVED.iter().any(|r| *r == name)`. That redundancy is what made the
  trailing-underscore branch in `field_ident` unreachable. Watch for it when editing.
- **`to_snake` does not strip a leading underscore** — hence `field_ident`'s separate
  leading-underscore branch.
- **`field_ident`'s output is always wire-safe** because the emitter writes
  `#[serde(rename = "{prop_name}")]` whenever the field name differs from the
  property name (`emit.rs` ~line 1185). Serde handles empty-string and numeric
  renames correctly (round-trip verified).
- **`clippy::pub_underscore_fields` (pedantic) fires on `pub _meta`.** Any fallback
  identifier must not start with `_`.
- **`type_ident` uses the trailing-underscore convention** (via `is_keyword` → push
  `'_'`), because `Self_` / `crate_` are legal *type* names. `field_ident` needs the
  `r#`/underscore *split* because it handles *field* names. Do not unify them.
- **`module_ident("draft") == "draft"`**; other revisions → `v2025_11_25` style.
- **`build.rs` `#[path]`-includes shared sources**, so those files may not reference
  `crate::` and may only use `[build-dependencies]` crates.
- The deleted `naming.rs` used `field_ident("2fa") == "_2fa"` (leading underscore kept,
  unlike the live code which trims it). The live code returns `"2fa"` for that input,
  which is **not a legal Rust identifier** — see §3.2b. If you port a case from the
  dead file, port the *expected value* (`"_2fa"`), not the live behaviour.
- `to_snake` behaviour, verified with rustc 1.98.1 edition 2024:

  | input | `to_snake` | `field_ident` | legal Rust? |
  |---|---|---|---|
  | `"2fa"` | `"2fa"` | `"2fa"` | **NO** — see §3.2b |
  | `"$schema"` | `"_schema"` | `"schema"` | yes |
  | `"_meta"` | `"_meta"` | `"meta"` | yes |
  | `"self"` | `"self"` | `"self_"` | yes |
  | `"Self"` | `"self"` | `"self_"` | yes |
  | `"super"` | `"super"` | `"super_"` | yes |
  | `"crate"` | `"crate"` | `"crate_"` | yes |
  | `"gen"` | `"gen"` | `"r#gen"` | yes |
  | `"type"` | `"type"` | `"r#type"` | yes |
